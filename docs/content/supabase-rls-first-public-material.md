## Telegram-пост

**Авторизация работает. Но второй пользователь всё равно видит чужие данные.**

На тестовом проекте с Supabase создали две отдельные сессии.

Пользователь A создал свою запись. Под пользователем B проверили, можно ли получить к ней доступ напрямую.

Получилось:

**До исправления**
- чтение чужой записи: 1
- изменение: 1
- удаление: 1

То есть успешный вход в аккаунт сам по себе не изолировал данные пользователей.

Исправили правило доступа и повторили те же проверки под тем же пользователем B.

**После исправления**
- чтение: 0
- изменение: 0
- удаление: 0

Но на этом проверку не закончили. Отдельно убедились, что B по-прежнему видит собственную запись. Иначе можно было бы «исправить» проблему, просто сломав доступ всем.

Это тестовый проект, не клиентский кейс. Результат относится только к этому сценарию.

**Работает — ещё не значит готово к запуску.**

## Короткий ролик 30–45 секунд

### Хук

«Ты сделал авторизацию в Supabase. Но значит ли это, что один пользователь не увидит данные другого?»

### Сценарий

1. Показать User A и его запись.
2. Переключиться на User B.
3. Показать результат: `READ 1 / UPDATE 1 / DELETE 1`.
4. Фраза: «Вход работает. Изоляция данных — нет».
5. Показать исправление RLS без длинного SQL.
6. Повтор: `0 / 0 / 0`.
7. Показать owner check: собственная запись B по-прежнему доступна.
8. Финал: «Сначала проверка. Потом запуск.»
