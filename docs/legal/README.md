## Что подтверждено по действующим источникам на 17.08.2026

1. Ст. 18 ч. 5 152-ФЗ: при интернет-сборе ПДн граждан РФ операции первичной записи/систематизации/накопления/хранения/уточнения/извлечения не должны выполняться через базы данных за пределами РФ, кроме установленных законом исключений.
2. Ст. 22 152-ФЗ: до начала обработки оператор в общем случае уведомляет Роскомнадзор; для обычной автоматизированной интернет-формы оставшиеся исключения не дают безопасного основания считать уведомление ненужным.
3. Ст. 12 152-ФЗ: трансграничная передача имеет отдельный уведомительный режим. Первичная локализация в РФ не отменяет требования ст. 12 к последующей трансграничной передаче.
4. Минцифры в письме от 12.05.2025 N П25-44929 прямо разделяет локализацию первичного сбора и последующую трансграничную передачу.
5. Yandex Cloud документирует регион Россия (`ru-central1`); Serverless YDB создается с `location_id: ru-central1`.
6. Для НПД отдельная ККТ не требуется в обычной модели НПД, но чек по полученному доходу формируется через «Мой налог» и передается заказчику.

Источники для пп. 1–5 зафиксированы в `docs/product/lead-backend-architecture-v1.md` ветки `product-v2-feature-matrix`; перед финальной публикацией юридического комплекта повторно проверить актуальную редакцию.

## Рабочий вывод для Vibe Release

До включения production-формы:
- инфраструктура первичного сбора должна быть фактически развернута в РФ;
- политика и согласие должны описывать реальный payload/storage/retention;
- уведомление Роскомнадзора подается/актуализируется под фактическую автоматизированную обработку;
- если клиентские ПДн когда-либо будут отправляться иностранному получателю, отдельно закрывается режим ст. 12.

Чтобы не создавать трансграничную передачу ПДн только ради уведомления менеджера, Telegram V1 получает лишь общий сигнал вида `Новая заявка · STUCK → FINISH. Откройте панель менеджера.`
